# Git and GitHub workflow

The GitHub repository contains the application source and setup instructions. Local credentials, installed packages, and generated files stay on your computer.

## Files to commit

- `backend/app.py` and `frontend/src/` — application source
- `frontend/package.json` and `frontend/package-lock.json` — frontend dependencies
- `requirements.txt` — Python dependencies
- `.env.example` — safe configuration template
- `README.md`, `GIT_WORKFLOW.md`, and `.gitignore` — project documentation and Git rules

These are already included in the repository. `frontend/dist/` is generated by `npm run build`; it can be recreated and is not committed.

## Keep these files private or local

- `.env` and other `.env.*` files — may contain MongoDB credentials, admin passwords, or Flask secrets
- `.venv/` — local Python virtual environment
- `frontend/node_modules/` — installed JavaScript dependencies
- `frontend/dist/` and `frontend/.vite/` — generated build and cache
- `__pycache__/` and `*.py[cod]` — generated Python cache
- `*.sqlite`, `*.sqlite3`, and `*.db` — local database files; this project uses MongoDB

The `.gitignore` file prevents these from being staged by normal `git add` commands. `.env.example` is explicitly allowed so others can copy it to their own `.env`.

## Set up `.env` after cloning

From the project directory, create a local configuration file only if you do not already have one:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Fill in your own admin and MongoDB settings. Do not copy real passwords into `.env.example` or commit `.env`.

## Commit and push changes

Run these commands from the project directory in PowerShell:

```powershell
git status
git add -A
git status
git diff --cached --check
git diff --cached --name-only
git commit -m "Describe your changes"
git push
```

Before committing, confirm that `.env`, `.venv`, `node_modules`, `dist`, and database files do not appear in the staged-file list. Check that `.env` is ignored with:

```powershell
git check-ignore -v .env
```

If a private file was staged accidentally, unstage it before committing without deleting it from your computer:

```powershell
git restore --staged .env
```

If a secret has already been pushed to a public repository, change that credential; deleting the file in a later commit does not erase it from Git history.
